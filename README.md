# Book Wise — Python service

Speech and AI service of **Book Wise**, a mobile app that helps primary-school children practise
reading. It measures reading speed and accuracy from the child's voice in real time and generates
comprehension tests with an LLM.

It is one of three repositories:

| Repository | Role |
|---|---|
| `book-wise-mobile` | React Native / Expo app for students and teachers |
| `book-wise-be-java` | REST API, database, file storage, authorization |
| `book-wise-be-python` (this one) | Speech recognition, AI test generation, stress check |

## Features

- **Reading-speed sessions (WebSocket).** The app streams microphone audio; the service recognizes
  it with [Vosk](https://alphacephei.com/vosk/) using *guided decoding* (a grammar built from the
  reference text) and aligns the recognized words with the text on the fly (Levenshtein alignment
  with a small hold-back buffer). Every word gets a status — `correct`, `error`, `skipped`,
  `not_in_vocabulary` or `not_reached` — which is pushed to the app live and used to compute
  words per minute and accuracy.
- **Substitution check.** After the session ends, two recognizers without a grammar (open-vocabulary
  Vosk and Moonshine Base UK) re-check the words the grammar accepted. A word is marked as an error
  only when both of them disagree with the text.
- **Stress check.** In the background, the full recording is force-aligned with
  Montreal Forced Aligner, and a trained classifier decides whether each word was read with the
  correct stress. Progress and results are reported to the Java backend, which the app polls.
- **Comprehension quiz.** 1–3 questions about the part of the text the child actually read,
  generated by Gemini right after the session.
- **Book tests.** Consumes test-generation requests from RabbitMQ (sent by the Java backend),
  extracts text from the book in MinIO, generates questions with Gemini and publishes the result.
- **Excerpts.** Picks a random ~300–340-word excerpt from a book assigned to the child, or uses a
  fragment assigned by the teacher.

## Tech stack

Python 3, FastAPI + Uvicorn, Vosk (`vosk-model-uk-v3-lgraph`), Moonshine via `transformers` +
PyTorch (CPU), Montreal Forced Aligner, scikit-learn, `ukrainian-word-stress`, PyMuPDF,
aio-pika (RabbitMQ), MinIO, Gemini API.

## How it fits together

```
mobile ──WebSocket /ws/reading-speed (Supabase JWT)──▶ Python (:8001)
                                                         │ ├─ HTTP /internal/** + API key ─▶ Java (save attempt, stress progress)
Java ──RabbitMQ test_generation_request──────────────▶   │ ├─ MinIO (book files, session audio)
Java ◀─RabbitMQ test_generation_response──────────────   │ └─ Gemini API
Java ──HTTP /internal/book-paragraphs─────────────────▶  ┘
```

## Getting started

### Prerequisites

- Python 3.11+
- Docker (for RabbitMQ)
- MinIO and the Java backend running (see `book-wise-be-java`)
- A Gemini API key
- Optional: Montreal Forced Aligner, for the stress check (see below)

### 1. Start RabbitMQ

```bash
docker compose up -d            # RabbitMQ (:5672, management UI :15672, guest / guest)
```

### 2. Install dependencies

```bash
python -m venv .venv
source .venv/bin/activate

pip install -r requirements.txt

# Stress dictionary — must be installed WITHOUT dependencies (otherwise it pulls stanza + torch)
pip install --no-deps -r requirements-stress.txt

# Optional: substitution check (Moonshine). CPU-only PyTorch keeps the install small.
pip install torch==2.14.0 --index-url https://download.pytorch.org/whl/cpu
pip install -r requirements-hybrid.txt
```

Without the optional packages the service still works; the substitution check is skipped with a
warning in the log. It can also be disabled explicitly with `HYBRID_CHECK_ENABLED=false`.
The Moonshine model (~240 MB) is downloaded from Hugging Face on first start.

### 3. Download the Vosk model

```bash
./scripts/download_vosk_model.sh   # ~325 MB, into vosk_models/vosk-model-uk-v3-lgraph
```

The `lgraph` model is required: guided decoding needs a model with a dynamic graph.

### 4. Configure environment

Create a `.env` file in the repository root. Main variables (defaults in `core/config.py`):

```dotenv
# Auth (same Supabase project as the Java backend)
SUPABASE_URL=https://<project>.supabase.co

# Java backend
JAVA_BASE_URL=http://localhost:8080
JAVA_INTERNAL_API_KEY=<same value as INTERNAL_API_KEY in book-wise-be-java>

# LLM
GEMINI_API_KEY=<key>
# LLM_MODEL=gemini-3.8-flash

# RabbitMQ
RABBITMQ_HOST=localhost
RABBITMQ_PORT=5672
RABBITMQ_USER=guest
RABBITMQ_PASSWORD=guest
RABBITMQ_REQUEST_QUEUE=test_generation_request
RABBITMQ_RESPONSE_QUEUE=test_generation_response
RABBITMQ_EXCHANGE=test_generation_exchange
RABBITMQ_ROUTING_KEY=generate_test

# MinIO (endpoint without http:// prefix)
MINIO_ENDPOINT=localhost:9002
MINIO_ACCESS_KEY=minioadmin
MINIO_SECRET_KEY=minioadmin
MINIO_BUCKET=books
MINIO_SECURE=0

# Reading speed
VOSK_MODEL_PATH=vosk_models/vosk-model-uk-v3-lgraph
REFERENCE_TEXTS_DIR=resources/reference_texts
READING_SESSIONS_AUDIO_DIR=reading_sessions
TEMP_DIR=/tmp

# Stress check (optional)
STRESS_MODEL_PATH=resources/models/stress_model.joblib
MFA_BIN_DIR=<path to the bin directory of the MFA conda environment>
MFA_ACOUSTIC_MODEL=ukrainian_mfa
MFA_DICTIONARY=ukrainian_mfa
MFA_ALIGN_TIMEOUT_SECONDS=120
STRESS_MFA_CORPUS_DIR=stress_sessions/corpus
STRESS_MFA_OUTPUT_DIR=stress_sessions/output
```

### 5. Run

```bash
python main.py                  # http://localhost:8001
UVICORN_RELOAD=1 python main.py # auto-reload for development
```

On startup the service loads the Vosk, Moonshine and stress models and starts consuming
RabbitMQ. Auto-reload is off by default: a reload would drop all active reading sessions.

## Stress-check layer

The stress check needs [Montreal Forced Aligner](https://montreal-forced-aligner.readthedocs.io/),
which is distributed through conda:

```bash
conda create -n mfa -c conda-forge montreal-forced-aligner
conda activate mfa
mfa model download acoustic ukrainian_mfa
mfa model download dictionary ukrainian_mfa
```

Set `MFA_BIN_DIR` to the environment's `bin` directory (e.g. `~/miniforge3/envs/mfa/bin`).
The classifier is shipped in `resources/models/stress_model.joblib`. If MFA is not available,
reading-speed sessions still work; only the stress result is marked as failed.

## Endpoints

| Endpoint | Description |
|---|---|
| `GET /api/status` | Health check |
| `WS /ws/reading-speed?token=…&participant_id=…[&assignment_id=…][&text_id=…]` | Reading-speed session |
| `POST /internal/book-paragraphs` | Clean book text split into paragraphs (used by Java for teacher assignments) |

OpenAPI docs are disabled because the service is exposed publicly.

### Reading-speed protocol

1. The client connects with a Supabase access token. The server replies with a `reference`
   message: the text split into words, the title and the time limit.
2. The client sends binary frames with raw audio — 16 kHz, mono, 16-bit PCM.
   The server replies with `word_event` messages (`index`, `status`, `tentative`).
3. The client sends the text message `stop` (or the time runs out / the text is finished). The server sends
   `processing`, the final word events, `quiz` and then `result` with metrics and the saved
   attempt id, and closes the socket.

## Project structure

```

api/routes/             # status, reading_speed (WebSocket), internal

models/                 # Pydantic models

├── reading_speed_session.py            # One reading session: streaming recognition, finalize
├── alignment.py                        # Live alignment of recognized words with the text
├── substitution_check.py               # Open-vocabulary double check (Vosk + Moonshine)
├── stress/, stress_background.py       # Stress check (MFA + classifier), background runner
├── book_excerpt.py, catalog_excerpts.py, book_paragraphs.py, pdf_text.py
├── comprehension_quiz.py, test_generator.py, llm_service.py
└── java_client.py, minio_client.py, rabbitmq_*.py
resources/              # Reference texts, catalog excerpts, stress model
scripts/                # Model download, offline pipeline checks
```

## Offline checks

`scripts/` contains scripts that run the recognition pipeline on recorded audio without the
WebSocket and the app (`pip install -r requirements-dev.txt` first):

```bash
.venv/bin/python scripts/test_reading_speed_pipeline.py
.venv/bin/python scripts/test_substitution_check.py
```

They expect the benchmark recordings referenced at the top of each script.
